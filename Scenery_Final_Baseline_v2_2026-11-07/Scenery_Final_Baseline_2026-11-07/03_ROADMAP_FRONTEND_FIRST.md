# Scenery — خارطة تنفيذ مُحدّثة (Frontend First)
**الإصدار:** 2.0 | **التاريخ:** 2026-11-07

## قاعدة المشروع غير القابلة للتجاوز

**لا تُكتب وظائف Backend تشغيلية، ولا تنشأ Migrations أو قاعدة بيانات مشروع، ولا API إنتاجي، قبل عرض الـFrontend المكتمل تجريبيًا على العميل، جمع ملاحظاته، تنفيذها، والحصول على قبول صريح منه وتوثيقه.** يجوز التخطيط النظري لعقود البيانات أثناء بناء Frontend لتجنب إعادة العمل، ولكن ليس تنفيذ Backend.

## المراحل التنفيذية

### المرحلة A — تحديث مستندات التخطيط (المرحلة الحالية)

**المدخلات:** ملفات التخطيط القديمة، الوثيقة SRS 1.1، وسجل قرارات 1–60.  
**العمل:** تدقيق المعرفات WEB/HOME/CAT/PROD/CUSTOM/PRJ/CNT/ADM/CMS/LEAD/ALERT، تعديل SITEMAP وUSER_FLOWS، تغيير Roadmap Frontend-First، توحيد Open Questions وRisk Assessment دون إعادة تسمية معرّفات المصدر القديم.  
**المخرجات:** هذه الحزمة وتحديث ملفات المشروع لدى Codex بالبرومبت A.  
**معيار الانتهاء:** لا تعارضات صامتة، ولا اختراع متطلبات معتمدة، ولا كود.

### المرحلة B — Design System وUX

1. دراسة الشعار المرجعي وإعادة طلب النسخة الأصلية، واستخدام Instagram كمرجع بعد رؤية المنشورات فعليًا، لا تخمين.
2. نظام خطوط عربية وألوان وتباين ومسافات وحالات مكونات وGrid وBreakpoints وعناصر Gallery وإشعارات وإدارة.
3. تصميم Mobile-first للصفحات العامة، ثم Dashboard/CRUD/جدول وملاحظات ذات أحجام متعددة.
4. إعداد حالات Empty/Loading/Error/Success وfocus/hover/disabled/reduced-motion.
5. مراجعة الشكل مع صاحب المشروع قبل تطوير كل الصفحات.

### المرحلة C — Frontend كامل مع بيانات تجريبية واقعية

**صفحات عامة:** الرئيسية، المنتجات، التصنيفات، تفاصيل المنتج، الأعمال الخشبية، المشاريع، تفاصيل المشروع، صمّم حسب طلبك، من نحن، تواصل معنا، الخصوصية، الحالات المساعدة.  
**لوحة التحكم Demo:** نظرة عامة، المنتجات والتصنيفات، المشاريع، إدارة الصفحة الرئيسية والصفحات، FAQ والشهادات، الاستفسارات وتفاصيلها وإسنادها، الإشعارات، الموظفين والصلاحيات، الإعدادات، النشاط، الإصدارات وسلة المحذوفات، وعمليات الإدارة الجماعية.

**بيانات الـDemo:** مجموعة كافية من غرف النوم، السفرة، الانتريهات، الأثاث الخشبي، ومشاريع بألبومات مختلفة؛ أسماء ومواصفات وأسعار **افتراضية** وموسومة بوضوح، لا ادعاءات عن المصنع الحقيقي. فيديوهات demo مرخصة أو placeholder مُعلن. لا تنشئ عملاء حقيقيين أو تجري اتصالات واتساب تلقائيًا.

**تفاعلات Demo:** بحث وفلاتر، معرض الصور/فيديو، فتح/إغلاق القوائم، Tabs، نموذج استفسار مع تحقق محلي ورسالة «تجربة توضيحية — لم يُرسل»، مسودات Demo محلية واضحة، إظهار إخفاء الأقسام، نماذج إدارة للمعاينة؛ لا مزاعم بأن البيانات آمنة أو مستمرة عبر الأجهزة في مرحلة mock.

**اختبار المرحلة:** viewport مختلفة، keyboard، لمس، أداء صور الصفحة الرئيسية والـGallery، جميع روابط القائمة وFooter، منطق وضع السعر، انعدام تسريب محتوى مسودة في واجهة عامة Mock.

### المرحلة D — عرض العميل والمراجعات (Mandatory Approval)

1. إصدار رابط Demo مؤقت غير مفهرس ومخصص للمراجعة بعد التحقق من إمكانية الوصول له بأمان.
2. إرسال قائمة قصيرة بما هو تجريبي وما لم يُربط بعد مع Backend.
3. الحصول على تعليقات مسجلة لكل صفحة وعلى الموبايل والكمبيوتر.
4. تنفيذ التغييرات المتفق عليها، إصدار نسخة جديدة، ثم مراجعة ثانية إذا لزم.
5. توثيق اسم الشخص صاحب الاعتماد وتاريخ ونسخة UI المعتمدة، بدون افتراض الموافقة من السكوت.
6. **توقّف كامل عن Backend حتى G3.**

### المرحلة E — Backend Laravel/MySQL والتكامل

بعد G3 فقط: التأكد من الإصدارات، طبقة DB وMigrations، Authentication/Authorization، موديلات منتجات/تصنيفات/مشاريع وMedia/Revision، الاستفسارات والمرفقات الخاصة والإشعارات، CMS، Audit، نسخ احتياطي وخدمات بريد وتشغيل حسب الاستضافة. تُصمم التخويلات على السيرفر، ثم تُربط الواجهات المعتمدة.

- API/Controllers تحافظ على contract المرسوم في Demo.
- المدخلات والتحقق يتمان على الخادم أيضًا.
- تخزين الملفات بالـfilesystem abstraction مع إمكانية تغيير disk لاحقًا.
- التعامل مع Version History/Auto-save/concurrency وسلة المحذوفات يحتاج اختبارات بيانات وتفويض.
- لا مبيعات فعلية أو قاعدة بيانات تجارة إلكترونية في هذه المرحلة.

### المرحلة F — QA وUAT والإطلاق

- اختبارات وحدة وتكامل، صلاحيات، UX، موبايل ومتصفحات، وصول، SEO، صور وفيديو، أساسيات أمنية، وفشل البريد دون فقد الاستفسار.
- تجهيز المحتوى الحقيقي والموافقات القانونية والخصوصية، وتأكيد مزود الاستضافة والدومين وحدود وسائط وWorker/Queue وتخزين وBackup/Restore.
- توثيق مخاطر استثناء عدم تقييد محاولات تسجيل الدخول وغياب MFA؛ الحصول على موافقة مِلكية/تشغيلية واعية قبل الإطلاق.
- تجربة استعادة نسخة احتياطية، اختبارات إرسال واستعادة كلمة مرور، تفعيل HTTPS، فحص عدم ظهور ملف .env/أخطاء debug.
- تسليم إرشاد إدارة للمالك، وثيقة ما بعد التسليم وأي قصور معروف.

## معايير إنهاء كل Sprint

- قائمة مكتوبة بالملفات التي تغيرت وما الذي يعمل بالفعل وما هو Mock.
- مقارنة ملموسة مع قرارات النطاق ذات الصلة.
- اختبارات قابلة للإعادة وذكر الأجهزة/المتصفحات الواقعية أو المحاكاة.
- صور Screenshots من الموبايل والكمبيوتر للمراجعة لا تُخلط بصور المصنع.
- منع أي تسويق للأرقام/الشهادات التجريبية باعتبارها حقيقية.
